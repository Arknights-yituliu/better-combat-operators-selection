# PRTS 语料剥离非作战内容

**日期：** 2026-09-25
**任务：** 本仓库只做作战方向的信息整理与计算，但 `material_datas/PRTS/` 的干员页里混着大量剧情与养成内容，
每次 TAG 判定整篇读取都在为它们付上下文成本。把非作战内容从语料移除，并让爬虫今后不再产出，
同时保证全仓库 `文件:行号` 证据引用不失效。

**结果：** 932 个干员/召唤物文件里 431 个被改写；语料 148,032 行 → 85,054 行（−42.5%）、
7,384,237 字符 → 2,420,314 字符（−67.2%）。`results/operator-tags.json` 与
`docs/untagged-operators.md` 剥离前后**逐字节相同**。两轮独立复核各发现一批漏网的引用改写，
第二轮还发现审计判据本身无效；修完后 11,581 条 HEAD 侧引用 **0 失效、0 未解析**，
62 条指向已删行且逐条确认删的不是作战内容。

---

## 现状：剧情不在章节层，而在模组内部

章节级剧情（`干员档案`／`语音记录`／`干员密录`／`悖论模拟`）爬虫早已用 `STOP_SECTIONS` 整节丢弃，
残留的剧情全部藏在 `## 模组` 里，而 `## 模组` 占主文件 52% 行数。每个模组小节的结构是固定的：

```
### 佣兵的行囊
![](…uniequip_img…)            ← 模组立绘
![](…uniequip_type/art-x.png…) ← 类型图标
**ART-X**                       ← 类型码文本行（模式限定模组的唯一文本依据）
**佣兵的行囊**
**基础信息**  全文阅读          ← 标记行
<模组故事，26 行>               ← 剧情副本 A
![](…模组等级_1.png…)           ← 等级图标（同时是副本 A 的收尾）
生命 +130攻击 +54 / **特性追加：**…
![](…模组等级_2.png…) / 生命 +180… / 天赋【…】更新
![](…模组等级_3.png…) / 生命 +210… / 天赋【…】更新
**模组解锁任务**                ← 纯解锁条件
**解锁需求与材料消耗**           ← 纯材料图标
![](…模组等级_1.png…) / [道具图标]…龙门币8万
**基础信息** 关闭全文            ← 标记行
<模组故事，与副本 A 逐字节相同>   ← 剧情副本 B（重复）
```

标记行全仓库计数：`全文阅读` 499、`关闭全文` 499、裸 `基础信息`（证章简介）386。
即**每段模组剧情在语料里存了两份**。

## 剥离规则（`crawl_prts.py`）

| 内容 | 处理 | 字符占比 | 引用数 |
|---|---|---|---|
| 模组「解锁需求与材料消耗」块 | 删 | 31.6% | 0 |
| `精英化材料` + `技能升级材料` | 整节删 | 14.9% | 0 |
| 模组故事副本 A/B + 证章简介 | 删 | 5.5% | 1（本已锚错） |
| 模组等级图标行 | 改写为 `**模组等级N**` | 5.5% | 0（等级归属反而变清晰） |
| 模组立绘/类型图标 | 删 | 3.0% | 14（见下） |
| `后勤技能` | 整节删 | 1.4% | 0 |
| 模组解锁任务块 | 删 | 0.6% | 1（见下） |

`## 获得方式` **必须保留**——上线时间的来源（`_brief.md` 要求从该节解析），有 72 个引用原子落在该节。
`## 精通`（机械师、电弧）同样保留，有 31 个。三节被删的 `后勤技能`／`精英化材料`／`技能升级材料`
则是 **0**——这是它们可以整节删除的直接依据（统计口径：HEAD 侧引用原子按落点小节计数，
可由 `strip_prts_noncombat.py` 的索引与 `git show HEAD:` 复现）。

## 四个判错后修掉的坑

1. **材料块不能"删到下个标题"。** `涤火杰西卡/涤火杰西卡.md` 剥离前的第 524 行（现第 204 行）是一条真机制脚注
   （「此处游戏内原文是*不受技能攻击范围变化影响*，因语序颠倒、表述模糊，我们对其进行了修正」），
   紧跟在剧情副本 B 之后。规则收尾条件改成"遇到第一个既非空行也非图片的行即停"，
   并对任何含 `#cite_ref` 的行直接放行。

2. **类型图标行被当作证据引用。** 14 条引用（共 26 个原子）直接锚在 `uniequip_type/*.png` 上，用它证明模组的类型码
   （RA-α／ISW-α／PRO-Y／MAR-X／PUS-Y…）——而模式限定模组是要计入玩家 TAG 的。核查后确认
   **499 个类型图标无一例外**都在下一行跟着同名 `**<类型码>**` 文本行，所以删图片不丢信息，
   把那 14 处按内容重锚到文本行即可。

3. **`归溟幽灵鲨.md` 剥离前引用的第 261、268 行本来就锚错了。** 它被用来证明「ISW-α 模组1级」，实际指向的却是另一个
   模组（PUM-X「唱片」收藏箱）的材料行。重锚到 `**ISW-α**` 行。

4. **引用路径里的括号。** 初版匹配式把 `(` `（` 排除在路径字符之外，导致
   `阿米娅(近卫)/阿米娅(近卫).md` 的引用整段被跳过、停在剥离前的行号上（43 处）。
   放宽后配合"逐层剥掉前导括号再解析"的兜底；`_merge_to_docs.py` 里还有三处硬编码引用
   （含 `/` 作分隔符的 `374/411`），也一并纳入扫描范围。

## 复核发现的问题（第二轮修掉的坑）

第一轮交付后由独立子代理复核，结论是**剥离本身正确、引用改写有漏网**：它逐条比对 HEAD 与现状，
测得 16,728 个引用原子正确、**94 个仍是剥离前的行号**（占 0.56%）。更要命的是这些问题
**第一轮的 `--audit` 全部报"失效 0 条"**。根因有三层：

5. **解析失败被静默跳过。** 改写与审计都在 `look_up()` 返回 `None` 时 `continue`——对真正的外来引用
   （`docs/glossary.md:`、分文件互引）这是对的，但对一个"写法怪、其实指向 PRTS"的路径就是静默失败：
   它既不被改写，也不被审计，最后还报"0 失效"。实测 6,855 个匹配里有 **1,085 个解析失败**，
   全都隐形。现在 `look_up()` 改为"按 `/` 归一化后取最长可解析后缀"，并在审计里把
   **解析失败但文件名属于 PRTS 语料**的引用单列为 `未解析` 并让它非零退出——把静默失败变成红字。

6. **反斜杠路径。** `09-保人.md` 整份用了 Windows 分隔符（形如 `异客\异客.md` 加行号 472、473），
   一个都没被解析过。归一化后一并修复（该文件先前被整体跳过）。

7. **一条无空格的引用串会吞掉前一条。** 形如「星熊 374／411、可颂 169／198」的串里，
   贪婪匹配把「星熊的路径:行号、可颂的路径」整个当作"路径"，于是只有可颂被改写、
   星熊留在旧行号。把 `:` 排除出路径字符类后，两条各自成匹配。

8. **glob 盲区。** `official-fullmap-aura.md` 位于 `tag_pipeline/` 顶层，不在
   `player_tags/` 或 `official_tags/` 之下，从未进入扫描范围。教训是**按目录显式枚举**，
   不要靠"猜哪些文件有引用"。

## 第三轮：审计判据本身是错的

第二轮复核还指出一件更根本的事：**`--audit` 的判据是同一语反复**，所以上面那些"失效 0"
其实不构成证据。它当时用的是"新行号处的文本 == 旧行号处的文本"，而剥离保证
`new[map(x)-1] == old[x-1]` 对**任何在范围内的行号**都成立——无论它是改写后的还是漏改的。
于是该判断退化成"行号是否越界"，只抓得到越界那一种。复核用一个注入用例证明：把一个
`深海色/深海色.md:144`（应为 114）塞进测试文件，`--audit` 报"失效 0"。

现在改成**与 HEAD 对比**：取每条引用在 HEAD 侧的行号，按行映射算出它应变成什么，
再要求工作区确实带着这个值。这是唯一能区分"改写后"与"漏改"的判据——内容测试做不到，
因为两种解释在内容上完全一致。三个出口：

- **失效**：工作区没带上应有的值（漏改）——必须为 0；
- **未解析**：解析不到目标但文件名属于 PRTS 语料——必须为 0；
- **指向已删行**：原锚点所在行被剥离删除——每次改动剥离规则后人工过一遍其原文。

有意偏离机械映射的引用（改锚到真正支撑论点的行）登记在脚本内的 `ACCEPTED`，
当前 5 条，全部是本节前面提到的深海色与 `_brief.md` 示例行。

顺带修掉的三个实现 bug：`head_maps()` 把 `特殊机制/` 也纳入映射（那里根本没被剥离，
却因空行折叠被算出位移，导致 3 条误报）；范围引用按**原子集合**而非字符串比较
（否则未改动的 `:54-56` 与 `:54,55,56` 会被判为不同）；`--fix-stale` 改为按审计给出的
具体原子定点替换，不再整份重映射——原先那版会把同一串里已经改对的行号再映射一次。

## 验证手段

- **行映射一致性**：改写前后逐条断言"新行号处的文本 == 旧行号处的文本"，唯一允许的例外是
  等级图标行的有意改写。
- **全量审计**：`strip_prts_noncombat.py --audit` 取每条引用在 HEAD 侧的行号、按行映射算出它应当
  变成什么，再要求工作区确实带着这个值。当前 11,581 条：**0 失效、0 未解析**，另有 62 条指向
  被删行，逐条看过其原文——21 条图片行、18 条空行、20 条证章套话／剧情、3 条 `**基础信息**` 标记，
  **无一条是作战内容**。判据为何必须是与 HEAD 对比，见下方「第三轮」。
- **产物不变**：`results/operator-tags.json` 与基线逐字节相同，证明剥离不改判定结果。
- **生成文档**：`docs/player-tags-members.md` 归一化行号后与 HEAD 相同，差异仅三处人工改锚——
  两处深海色（`34,54-58`：所属势力【阿戈尔】与「召唤触手」天赋，原先锚在证章标题上并不支撑论点）
  与一处 `11-阻挡数5.md` 传入的年（原锚点在被删的 `uniequip_type` 图片行上）。
- **爬虫路径**：`strip_noncombat()` 对全部 932 个 HEAD 文件跑出的结果与磁盘完全一致，
  即语料与"重新抓一遍"的产物等价，`--force` 重抓不会把噪声带回来。

## 教训

- **删除行会平移行号**，而本仓库的证据层就是 `文件:行号`。剥离必须和引用改写是同一个原子操作，
  且改写要有可证明的正确性判据（文本一致性），不能只靠"看起来对"。
- **"检查通过"必须先证明检查覆盖了全部输入。** 第一轮的 `--audit` 报 0 失效，却有 94 个原子是旧的：
  它对解析失败的引用一律跳过，于是"看不懂的"和"没问题的"在报告里长得一模一样。
  凡是 `if 解析不了: continue` 的扫描器，都必须把跳过数单独报出来，否则绿灯没有意义。
- **检查的判据必须能区分"对"和"错"，而不是恒真。** 第二轮的教训更深一层：把
  "文本一致"当作判据时，该式对正确与漏改的引用同时成立，检查便退化成只会报越界。
  写断言时先问一句：**有没有一个反例能让它失败？** 举不出反例的断言等于没有断言。
- `reverify.py check` 只做**越界**检查（行号 > 文件行数才报错），而绝大多数错误行号**仍在文件范围内**，
  它发现不了。所以需要与 HEAD 对比的 `--audit`。
- **独立复核值得做。** 本轮 7 个坑里有 5 个（静默跳过、反斜杠、贪婪吞并、glob 盲区、逐文件误映射）
  是自己写的工具自己查不出来的——同一个错误假设同时写在检测器和被检物里。
- 生成物不要手工改引用：`docs/player-tags-members.md` 由分文件重生成，其中还有
  `_merge_to_docs.py` 内嵌的硬编码引用，改分文件不够，脚本里的也要一起改。
- Windows 上 `Path.write_text` 会把 `\n` 翻成 `\r\n`。若先把行拼成 `\r\n` 再交给它，
  会写出 `\r\r\n`（`splitlines()` 于是把行数算成两倍）——用 `newline=""` 显式写，或干脆拼 `\n`。

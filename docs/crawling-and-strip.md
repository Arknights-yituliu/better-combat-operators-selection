# 爬取与语料剥离

> 用途：PRTS 爬虫的内部机制、踩过的坑，以及非作战内容的剥离规则与证据层审计纪律。
> 开工时**不必读本文**——按 `AGENTS.md` §一 取开工件；爬取或改剥离规则时按需查本节。

## 一、爬虫要点（`crawlers/crawl_prts.py`）

- PRTS 需要**完整浏览器请求头**（`User-Agent` + `Accept` + `Accept-Language` + `Referer` 四者齐全，只给 UA 仍被拒），并限速（默认 1.2–2.8 秒／请求）。不要紧循环爬取。
- 干员信息框是纯 JS 渲染，HTML 里没有稀有度／职业。二者改由 PRTS 的 Semantic MediaWiki 接口一次批量取回（`api.php?action=ask&query=[[分类:干员]]|?稀有度|?职业|limit=600`，同样需要浏览器头）。**分支、势力、上线时间不在 SMW 里**，取自页面自身表格（特性 → 分支、属性 → 势力、获得方式 → 上线时间）。
- 标题被包在 `<div class="mw-heading">` 里，不是 `h2` 的直接子节点——分段时要先解包。
- 页面里有大量 `display:none` 隐藏 span，分三类：算法说明（`*_算法_2`）、潜能升级数值（`*_潜能_2`）、tooltip 释义（`.mc-tooltips`）。**必须两趟清理且顺序不能反**：先删隐藏 span（数据单元格里的「潜能」类除外），再把剩下的潜能 span 换成可见的 `〔潜能提升后：…〕` 标记。先转潜能会把 tooltip 正文烤进保留内容。
- 隐藏 span 可以嵌套，且 `select()` 返回的是快照——遍历中 `decompose()` 父节点后，子节点仍会被访问。用 `el.decomposed` 判断后跳过。
- `markdownify` 会**静默丢弃 `<td>` 内的图片**（召唤物页的「持有者」格就是纯图片链接）。转换前把纯图片链接的 `title` 属性注入为文本节点。
- 复选框开关（`显示算法` 等）要在「吃掉 input 的通用选择器」**之前**删除，否则检测条件失效、标签文本残留。
- Windows 上 `os.replace` 覆盖刚写出的文件会偶发 `PermissionError`（杀毒／索引服务短暂占用）——包一层重试（10 次、1 秒起递增）。`_manifest.json` 每处理完一名干员就重写，因此长批任务天然幂等，崩了重跑即续。
- 信息框在桌面版与 `.nodesktop` 移动版各渲染一份，两份都在静态 HTML 里——`nodesktop`／`navbox`／`#toc` 一并剔除。
- 召唤物页文件名可能含括号（`Mon3tr(凯尔希的召唤物)`）、中文引号（`“清平”`）、点号（`龙腾.F`）——`sanitize_filename()` 把 Windows 非法字符映射成全角。
- **验收清单**：页头 `> 稀有度: N | 职业: X` 在；特性／天赋／技能／模组四节在；召唤物页「持有者」格显示持有者名；数据行里没有 `术语:`／`异常效果:` 文本泄漏。

### 干员清单的来历

`docs/operators.txt` 由 PRTS 筛选器导出的卡片列表片段提取（每项一个 `class="short-container"` 块，名称与链接文本始终相同），格式 `干员名 https://prts.wiki/w/干员名`。**「哪些是干员、哪些是召唤物」以 wiki 的分类为准**：`Category:干员` 与 `Category:召唤物` 做集合运算，不靠游戏知识判断。曾据旧知识误以为 Mon3tr／Miss.Christine／支援机械是召唤物——查其 wikitext 后确认它们是正式干员（Mon3tr 实装于 2025-04-07，召唤物形态是另一页 `Mon3tr(凯尔希的召唤物)`）。**名单知识有保质期，卡片数据比记忆可靠。**

## 二、语料剥离（`crawl_prts.py` 的 `plan_strip()`／`render_strip()`／`strip_noncombat()`）

**为什么剥离**：本仓库只做作战方向的信息整理与计算，但干员页里混着大量剧情与养成内容，每次判定整篇读取都在为其付代价。剥离后 932 个文件里 431 个被改写，语料 148,032 → 85,054 行（−42.5%）、字符 −67.2%；`results/operator-tags.json` 与剥离前**逐字节相同**。

**剧情藏在哪**：章节级剧情（`干员档案`／`语音记录`／`干员密录`／`悖论模拟`）早已由 `STOP_SECTIONS` 整节丢弃；残留的全部藏在 `## 模组` 里（占主文件 52% 行数），且每段模组剧情在语料里存了两份（`全文阅读`／`关闭全文` 标记之间各一份）。

**剥离规则**：

| 内容 | 处理 | 依据 |
|---|---|---|
| 模组「解锁需求与材料消耗」块 | 删 | 引用数 0 |
| `精英化材料` + `技能升级材料` | 整节删 | 引用数 0 |
| 模组故事副本 A/B + 证章简介 | 删 | 引用数 1（本已锚错） |
| 模组等级图标行 | 改写为 `**模组等级N**` 文本行 | 等级归属反而变清晰 |
| 模组立绘／类型图标 | 删 | 类型码保留为一行 `**ART-X**` 文本 |
| `后勤技能` | 整节删 | 引用数 0 |
| 模组解锁任务块 | 删 | 引用数 1（已重锚） |

`## 获得方式` **必须保留**（上线时间来源，有 72 个引用落在该节）；`## 精通`（机械师、电弧）同样保留（31 个引用）。三节被删的内容引用数都是 0——这是整节删除的直接依据（统计口径：HEAD 侧引用原子按落点小节计数）。

### 剥离时踩过的坑

1. **材料块不能「删到下个标题」**——块后可能紧跟真机制脚注（涤火杰西卡那条「不受技能攻击范围变化影响」的原文修正）。收尾条件改成「遇到第一个既非空行也非图片的行即停」，含 `#cite_ref` 的行直接放行。
2. **类型图标行曾被当作证据引用**：14 条引用锚在 `uniequip_type/*.png` 上以证明模组类型码——而模式限定模组要计入玩家 TAG。499 个类型图标无一例外都在下一行跟着同名 `**<类型码>**` 文本行，删图片不丢信息，按内容重锚到文本行即可。
3. **引用路径里的括号**：初版匹配式把括号排除在路径字符外，导致 `阿米娅(近卫)/阿米娅(近卫).md` 整段被跳过（43 处）。放宽后再逐层剥前导括号兜底。
4. **解析失败被静默跳过**：改写与审计都在解析失败时 `continue`——对真外来引用（`docs/glossary.md:`、分文件互引）是对的，但对「写法怪、其实指向 PRTS」的路径就是静默失败。改为「按 `/` 归一化后取最长可解析后缀」，并把**解析失败但文件名属于 PRTS 语料**的引用单列为「未解析」、让审计非零退出。
5. **反斜杠路径**（`异客\异客.md`）整份文件被跳过——归一化后修复。
6. **无空格的引用串会吞掉前一条**（「星熊 374／411、可颂 169／198」）——把 `:` 排除出路径字符类。
7. **glob 盲区**：`official-fullmap-aura.md` 在 `tag_pipeline/` 顶层，不在 `player_tags/`／`official_tags/` 之下，从未进入扫描范围。**按目录显式枚举（`REF_GLOBS`），不要靠猜**；新增目录时必须同步，漏一个就是整批引用静默保留旧行号。

## 三、证据层审计（`crawlers/strip_prts_noncombat.py --audit`）

**判据必须是与 HEAD 对比**：取每条引用在 HEAD 侧的行号，按行映射算出它应当变成什么，再要求工作区确实带着这个值。

**不要**用「新行号处的文本 == 旧行号处的文本」——剥离保证 `new[map(x)-1] == old[x-1]` 对任何在范围内的行号都成立，无论它是改写后的还是漏改的；那样的检查只会发现越界，正是本仓库踩过的坑（第一轮报「失效 0 条」而实际有 94 个旧行号）。

`--audit` 报三类：

- **失效**（应为 0）：工作区没带上应有的值，即漏改；
- **未解析**（应为 0）：解析不到目标、但文件名属于 PRTS 语料——「看不懂就当没问题」的静默跳过；
- **指向已删行**（每次改动剥离规则后需人工过一遍原文）：原锚点所在行被剥离删除，逐条看删的是不是作战内容。

有意偏离机械映射的引用（改锚到真正支撑论点的行）登记在脚本内的 `ACCEPTED`，新增即视为一次显式裁定。

**配套铁律**：删除行会平移其后行号——**剥离与引用改写必须是同一个原子操作**。任何再次剥离都要同时跑改写与审计；重爬场景**不跑 `--fix-stale`**（它会回退已做好的正确重锚）。

## 四、通用教训

- **「检查通过」必须先证明检查覆盖了全部输入**：凡是 `if 解析不了: continue` 的扫描器，都必须把跳过数单独报出来，否则绿灯没有意义。
- **检查的判据必须能区分「对」和「错」，而不是恒真**：写断言时先问「有没有一个反例能让它失败」。举不出反例的断言等于没有断言。
- **独立复核值得做**：本轮 7 个坑里有 5 个是自己写的工具自己查不出来的——同一个错误假设同时写在检测器和被检物里。
- **生成物不要手工改引用**：合并文档由分文件重生成，`_merge_to_docs.py` 里还有内嵌的硬编码引用，改分文件不够。
- Windows 上 `Path.write_text` 会把 `\n` 翻成 `\r\n`；若先拼好 `\r\n` 再交给它，会写出 `\r\r\n`（`splitlines()` 于是把行数算成两倍）——用 `newline=""` 显式写，或干脆拼 `\n`。

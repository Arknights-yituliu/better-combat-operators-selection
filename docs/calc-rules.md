> 本文收录本项目的**计算规则**：结算层位与总式、游戏文本到计算因素的映射、从面板到结果的演算流程，以及影响计算的未定项索引。
> 上游依据：PRTS 机制页快照 `material_datas/PRTS/_rules/`——`游戏数据基础.md`（伤害公式、攻速公式）、`作战机制.md`（伤害计算表、帧率）、`游戏数据基础／属性计算例子.md`（官方算例）、`属性.md`、`就近取整.md`；项目内成文见各 `material_datas/tag_pipeline/player_tags/NN-*.md` 的**计数方式**与 `_reverify/rules.md`。
> 边界：各 TAG 的**数值门槛**不在本文，见 `docs/player-tags-specify.md` 与各 `NN-*.md` 评定标准；游戏术语见 `docs/glossary.md`；「（待验证）」的标注范围见 `docs/concept.md:33`；逐条复算与并列记录见根目录 `待验证复算.md`。

## 1. 符号、结算层与总式

### 1.1 符号

| 符号 | 含义 | 出处 |
|---|---|---|
| `X₀` | 面板攻击力（精英2 满级 ＋ 条件点名档位的固定属性；不含信赖/潜能） | `01-决战歼灭.md:20` |
| `a` | 直接加算项（固定值，如「攻击力+30」「攻击速度+8」） | `_rules/作战机制.md:404` |
| `b%` | 直接乘算项（百分比，同池相加） | `_rules/作战机制.md:405` |
| `c` | 最终加算项（绝对值，如鼓舞光环、对敌固定点数增伤） | `_rules/作战机制.md:406` |
| `d%` | 最终乘算因子（改写式，各自独立相乘） | `_rules/作战机制.md:407` |
| `s%` | 段倍率（技能/特性写明的「造成相当于攻击力 X% 的伤害」） | `_rules/游戏数据基础.md:900-958`（伤害公式） |
| `e` | 附加攻击力（伤害式中的固定附加项） | `_rules/游戏数据基础.md:900-958` |
| `T₀` | 理论攻击间隔（基础值，或被技能改写后的值） | `_rules/游戏数据基础.md:962-964` |
| `S` | 攻击速度（默认 100） | `_rules/游戏数据基础.md:975` |
| `T` | 实际攻击间隔 | `_rules/游戏数据基础.md:962` |
| `n` | 攻击次数 / 跳数 / 轮数 | `01-决战歼灭.md:18` |
| `m` | 倍率（伤害 ÷ 面板攻击力） | `01-决战歼灭.md:11` |
| `N_target` | 计入的目标数（默认 1） | `02-次数对策.md:7⑤` |

### 1.2 结算层与判据

| 层 | 公式 | 对应什么文本特征 | 判据 | 出处 |
|---|---|---|---|---|
| 直接加算 | `X₁ = X₀ + Σa` | 「攻击力+NN」「攻击速度+NN」等**固定值** | 给的是绝对值，不是百分比 | `_rules/作战机制.md:404`（阿「攻击速度+100」） |
| 直接乘算 | `X₂ = X₁ × (1 + Σb%)` | 「攻击力+X%」等 **X% 型提升** | 是「+X%」而非「提升至 X%」；**同池多个百分比相加后一次乘，不得连乘** | `_rules/作战机制.md:405`（黑「攻击力+180%」） |
| 最终加算 | `X₃ = X₂ + Σc` | 「额外加上（某单位）攻击力的 X%」类光环/鼓舞；对敌固定点数增伤 | 数值来源是**别的单位**的面板，或为固定点数 | `_rules/作战机制.md:406`（空）；`_rules/游戏数据基础／属性计算例子.md:51-58` |
| 最终乘算 | `X₄ = X₃ × Π d%` | 「提升至/提高至 X%」「造成伤害提升至 X%」及独立乘算因子 | 是改写式（值本身就是 d）；**该层多个因子独立相乘，不相加** | `_rules/作战机制.md:407`（推进之王「提高至380%」） |
| 最终效果·伤害乘算 | 百分比相加 | 「受到的伤害减少 X%」类减伤/易伤 | 官方在该行明写「百分比相加」，与上面四层算法不同 | `_rules/作战机制.md:413` |
| 最终效果·伤害重写 | 重写（按次数） | 「需要 N 次伤害击倒」类特殊生命值 | 伤害量被重写为计数，是「次数类敌人」的机制根源 | `_rules/作战机制.md:414` |

### 1.3 主式

```
间隔侧
  S = 100 + Σ（明文攻速来源）                        ← 攻速按直接加算（R2/R3）
  T = T₀ × 100 / clamp(S, 10, 600)                 ← 官方攻速公式

伤害侧（逐段，层位自内向外）
  X₀ = 面板攻击力（E2 满级 ＋ 条件点名档位固定属性；不含信赖/潜能）
  X₁ = X₀ + Σa                                      ← 直接加算
  X₂ = X₁ × (1 + Σb%)                               ← 直接乘算（同池相加）
  X₃ = X₂ + Σc                                      ← 最终加算
  X₄ = X₃ × Π d%                                    ← 最终乘算（独立相乘）
  A_seg = X₄ × s% + e                               ← 官方「基本伤害」式
  m_seg = A_seg ÷ X₀                                ← 倍率定义

合成
  总倍率 = Σ_seg ( m_seg × n_seg ) × N_target        ← 段数求和 × 目标数
```

`m_seg = A_seg ÷ X₀` 是「层位语言」与「倍率语言」之间的桥：层位描述属性怎么叠，倍率描述相对面板的产出；`X₀` 取裸面板使倍率与面板数值解耦。

### 1.4 辅助式

```
间隔式     T = T₀ × 100 / clamp(S, 10, 600)；S = 100 + Σ攻速
次数式     n = round(持续 ÷ T)                       ← 四舍五入、含首击
段数式     段数 = Σ(每次攻击段数 × 攻击次数)
           每次攻击段数 = 命中数 × (1 + 每击附带段数)
跳数式     跳数 = 覆盖时长 ÷ 结算间隔（刷新式持续伤害取技能内覆盖时长）
窗口式     连斩/多段 = 段数 × 段间隔；周期性 = 跳数 × 跳间隔
           弹药制 = 弹药数 ÷ 每次消耗 × T；弹药倾泻 = 实际倾泻耗时
弹药式     轮数 = 弹药数 ÷ 每次消耗
期望式     期望次数 = 触发率 × 触发机会
过载分段式 时间型：[0, T_技能/2) 为前半、[T_技能/2, T_技能] 为后半
           弹药型：自第 (N/2 + 1) 枚起为后半（弹药剩余量降至一半时触发）
```

### 1.5 两条通用读法

1. **「层」与「链」不是一回事**。「层」回答**和谁相加**，「链」回答**乘进哪个量**。攻击速度按直接加算处理，但它不进 `X` 链，只进 `S`；「攻击力+X%」既在直接乘算层，又乘进 `X` 链。把攻速当乘算因子或乘进倍率，是结构性错误。
2. **改写式的修正规则**：最终乘算层的数值先修正——「提升至/提高至 X%」的 `d = X%`；「±X%」的 `d = 1 ± X%`（如 −40% → ×60%）。凡减益写成负数者，一律先加 1 再进 `d`（`_rules/游戏数据基础／属性计算例子.md:15,32`）。

### 1.6 官方算例对照

| 官方算例 | 算式 | 验证的层 | 出处 |
|---|---|---|---|
| 慕斯＋槐琥减攻 | `1000 × (1 − 40%) × 60% = 360` | 直接乘算与最终乘算分属两池 | `_rules/游戏数据基础／属性计算例子.md:34-36` |
| 真银斩被双重减攻 | `1000 × (1 − 40% + 200%) × 60% = 1560` | 「攻击力+200%」与「−40%」同池相加；最终乘算独立 | `_rules/游戏数据基础／属性计算例子.md:41` |
| 空为真银斩银灰加成 | `1000 × (1 + 200%) + 500 = 3500` | 最终加算位于直接乘算之后、最终乘算之前 | `_rules/游戏数据基础／属性计算例子.md:58` |
| 空＋双重减攻 | `(1000 × (1 − 40% + 200%) + 500) × 60% = 1860` | 四层顺序的完整串联 | `_rules/游戏数据基础／属性计算例子.md:62` |

## 2. 游戏文本 → 因素映射表

### 2.1 读法与列义

- 用法：拿到干员的特性/天赋/技能/模组原文后，按「游戏文本模式」一列逐句对号入座，得到该句的**因素类别**与**层位/计算位置**，再把全部因素装进 §1.3 的主式。
- 四张表按因素类别分组（攻击力与伤害量 / 攻速与间隔 / 段数次数与跳数 / 窗口弹药过载与条件）；「判定要点与常见坑」取自复算与因素审计的实际错例。
- 示例中的编号一律为 `文件:行号`（PRTS 相对路径）；涉及未定项的行在末列指到 §5。
- 行文中的「攻击力/攻速」等词指 PRTS 原文用词，不另行解释术语（术语以 `docs/glossary.md` 为准）。
- 注意区分字母编号：各表行内序号（如 `C1`）与 §5 的冲突编号（`C1`–`C10`）字母相同但分属不同表；引用冲突时一律带「§5」前缀。

## 3. 演算流程

### 3.1 流程表

| 步骤 | 输入（PRTS 哪节） | 操作 | 输出 | 常见错误 |
|---|---|---|---|---|
| 0 面板 | `## 属性` 属性表 | 按表头定位「精英2 满级」列取攻击力；不含信赖、潜能；即使条件只要求精英1 仍取 E2 | `X₀` | 取错列；混入信赖/潜能；硬编码列下标 |
| 1 攻速/间隔 | `## 属性` 攻击间隔行；`## 特性`/`## 天赋`/`## 技能`/`## 模组` | 收集全部明文攻速与间隔改写 → `S`、`T` | `S`、`T` | 漏计模组**档位**攻速；漏计对己生效的友方攻速；把攻速乘进倍率；同一条目出现两套 `S` |
| 2 次数/段数/跳数 | `## 技能`（持续、弹药）；`## 天赋`/`## 模组`（周期结算） | 按 §1.4 公式计数 | `n`、段数、跳数、轮数 | 用未取整次数参与后续乘算；`⌊⌋` 与四舍五入混用不并列；漏「每击附带」段；刷新式 DoT 按单次施加跳数 |
| 3 逐因子摆位 | `## 特性`/`## 天赋`/`## 技能`/`## 模组` 全部数值 | 每句按 §2 映射表定层：固定值→`a`、X% 型→`b`、外源固定→`c`、提升至/独立乘算→`d`、段倍率→`s%` | 每段倍率 `m_seg` | **同池连乘**；「提升至 X%」写成 `×(1+X%)`；把攻速塞进倍率；X/Y 模组档位叠乘；条件性档位无理由计入 |
| 4 窗口/过载/弹药 | `## 技能`（持续/弹药/过载）；`docs/glossary.md` 过载条 | 定窗口与分段（§2.5 D3/D4） | 窗口内的段数、次数与分段配置 | 过载段漏计；开技瞬间等「另计」项无理由排除 |
| 5 求和与相乘 | 前四步产物 | `总倍率 = Σ(m_seg × n_seg) × N_target`；概率项用期望 | 总倍率、段数、次数 | 群攻×目标数一律乘（D1）；概率项按满触发或直接忽略（C7）；同层因子在求和后又乘一次 |
| 6 与门槛对照 | `docs/player-tags-specify.md` 与目标 `NN-*.md` 评定标准 | 只读门槛并比较，记录达线结论 | 达线/不达线 | 在本文另立门槛；跨门槛不写；涉及 §5 未定项者只给一套值 |

### 3.2 各步细则

- **取整与量纲**：百分比保留到 0.1%、秒保留 2 位、× 保留 2 位；整数单位（下/发/段/枚/次/轮/跳）取整并给算式（`_reverify/rules.md:51`）。
- **计算式写法**：一律显式写取整步骤，形如 `15÷2.13≈7.04→7 下（四舍五入）`（`_reverify/rules.md:91`）。
- **取值定位**：技能数值取专精三（Rank Ⅲ）；属性表按表头定位列（「精英2 满级」），不得硬编码下标；模组数值行为多字段连写、按内容切分（`_reverify/rules.md:56`）。
- **并列**：拿不准的不硬判——给出两套算法与各自结果，或标注所属未定项（§5）。

### 3.3 演算样板

**样板一：号角 3 技能（弹药制＋过载分段＋条件档）**

```
步骤 0  面板        X₀ = 936（E2 满级列第 5 列，号角/号角.md:40）
步骤 1  攻速/间隔   所选档位无攻速词条 → S = 100 → T = 2.4 × 100/100 = 2.4 秒
方法：技能为弹药制（10 枚，号角/号角.md:113），跳过次数式，按弹药式计数
步骤 3  层位        天赋「军事要塞」X模组3级 攻击力+28%（号角/号角.md:59）→ b 池单因子 (1+0.28)
                    技能每击 240% 物理溅射（s%）；过载额外 60% 法术溅射（同段附加）
步骤 4  过载分段    弹药型：自第 6 枚起为过载段
                    前半 5 枚：240% × 1.28 = 3.072 → 5 × 3.072 = 15.36
                    后半 5 枚：(240% + 60%) × 1.28 = 3.84 → 5 × 3.84 = 19.20
步骤 5  求和        15.36 + 19.20 = 34.56 → 3456%
步骤 6  条件档      目标被自身阻挡时 特性追加提升至110%（号角/号角.md:217）→ ×1.10 → 3801.6 → 3802%
        未定项      档位固定属性 攻击+N 折入与否见 §5 C6；10 枚全于过载期倾泻时为 10 × 300% × 1.28 = 3840%
```

**样板二：怒潮凛冬 3 技能（同池相加＋逐击递增）**

```
步骤 3  层位   技能「攻击力+100%」、第二天赋「万众巨潮」+28%、每击后「攻击力额外+30%」同属直接乘算池
                （怒潮凛冬/怒潮凛冬.md:126,63）→ 每击倍率 = 240% × (1 + 1.00 + 0.28 + 0.30×(k−1))
步骤 3′ 逐击写开
       第 1 击  240% × (1 + 1.00 + 0.28)             = 240% × 2.28
       第 2 击  240% × (1 + 1.00 + 0.28 + 0.30)      = 240% × 2.58
       …第 5 击                                        = 240% × 3.48
步骤 5  求和   240% × (2.28 + 2.58 + 2.88 + 3.18 + 3.48) = 240% × 14.4 = 3456%
错误对照       把天赋 +28% 留在池外、先求五击总和再整体乘：
               240% × (2.00 + 2.30 + 2.60 + 2.90 + 3.20) × 1.28 = 240% × 13.0 × 1.28 = 3993.6%
               ——同池因子被连乘，结果偏高（正确 3456%）
```

## 4. 其余规定

### 4.1 面板与阶段

- 面板攻击力＝精英2 满级 **＋ 条件点名模组档位的固定属性（攻击+N）**；不含信赖与潜能；即使条件只要求精英1 仍按 E2 面板与 E2 档（`01-决战歼灭.md:20`）。面板并入档位固定属性后**倍率数值不变**，仅面板数字与绝对伤害随之更新。
- **模组与潜能的选档标准**：模组按「对**本 TAG** 有帮助的最高档」取用——某档开始对该 TAG 有帮助、更高档若对该 TAG 无新增帮助则不取该高档；并把所选档写进条件。潜能同理：某潜级的加成对该 TAG 有帮助 → 计入计算并在**条件**写明「N潜」；同一干员的不同 TAG 可依据不同潜级；多个潜级均对该 TAG 有帮助时取最高潜级；**干员默认即为 1 潜（基准），帮助效果在基准即具备时不写潜级，条件只写 ≥2 的所需潜级**。潜能的面板攻击加成不改变倍率类数值（不并入基准，必要时另列备查）。
- 同一条件并列多个模组档时，取对本 TAG 有帮助的最高档并把该档写进条件（不得两档叠乘）；条件要收紧阶段者须在条件与备注另行标注（§5 C5）。
- 技能数值取专精三 Rank Ⅲ（`03-吃拐一轮秒.md:10`）；属性表取值按表头定位列（`_reverify/rules.md:56`）。

### 4.2 攻速与间隔

- `实际间隔＝（基础间隔或技能改写后的间隔）× 100/(100＋总攻速)`；总攻速按加算（`01-决战歼灭.md:18`、`02-次数对策.md:7③`）。官方公式为 `T = T₀ ÷ (clamp(S,10,600) ÷ 100)`，两式等价（`_rules/游戏数据基础.md:960-979`）。
- 攻速只计 PRTS 明文来源：特性/天赋/技能/模组（含模式限定与模组档位），并写明来源与数值；技能内逐步叠加者按逐次结算累计（`01-决战歼灭.md:18`、`02-次数对策.md:7③`）。
- 总攻速参与间隔计算时按 10~600 夹逼；攻击速度属性自身下限为 20（`_rules/游戏数据基础.md:976-977`、`_rules/属性.md:18`）。
- 帧率 30FPS；1 帧 ≈ 0.033 秒、2 帧 = 0.066 秒（`_rules/作战机制.md:1096`；帧长异文见 §5 C1）。

### 4.3 取整与帧

- 次数/段数 `n = round(持续 ÷ 实际间隔)`，四舍五入、含首击；`⌊⌋` 不采用（`01-决战歼灭.md:18`、`02-次数对策.md:7①`、`03-吃拐一轮秒.md:25`）。
- 该约定是估算模型，与引擎的「就近取整（四舍六入五成双）」不等价；复算值的小数部分恰为 .5 时须在备注并列就近取整值，不得静默取一套（`_rules/就近取整.md`）。
- 计算式显式写取整步骤；量纲与小数位随原值（`_reverify/rules.md:51,91`）。

### 4.4 计数与段数

- 周期结算跳数＝覆盖时长 ÷ 结算间隔，与次数同取整；刷新式持续伤害按技能内覆盖时长计（`03-吃拐一轮秒.md:15`、`02-次数对策.md:7①`）。
- 附加伤害实例计段；每次攻击段数＝命中数 ×（1＋每击附带段数）——该条为**强制项**，随每一击附带的独立实例一律计入（`02-次数对策.md:7①`、`03-吃拐一轮秒.md:23`）。
- 过载技能按后半程分段；段数按前半程/后半程**各自的动作模型**计（范例：维什戴尔 2 技能——前半对单每次攻击 7 段＝1 正常＋3×2 余震、后半 4 连发对单 12 段）；概率触发按期望并写明算式。
- 攻击间隔、持续时长、窗口、段数基准、已计入的攻速来源等属**计数输入项**，不属乘区因子——因素审计只统计乘性/伤害性因素（见 §4.5）。
- 群攻×目标数仅在伤害可叠加于同一目标时乘算，否则按 1（`02-次数对策.md:7⑤`、`03-吃拐一轮秒.md:16,23`）。
- 概率触发按期望计，写明触发率与算式（`03-吃拐一轮秒.md:23`）。
- 独立结算的伤害源分别计数后合计（`02-次数对策.md:7⑥`）。
- 格数一律含自身格计；`02` 使用另一套索引，涉及距离门槛时两套并列（`01-决战歼灭.md:18`；§5 C3）。
- 弹药按「弹药数 ÷ 每次消耗」折算轮数；倾泻限原文写明者（`03-吃拐一轮秒.md:15,18`）。
- 窗口通用写法：15 秒窗口取输出最高的 15 秒；多阶段按最后一段结算完毕计；连斩型未给每击间隔按每击 ≤0.4 秒（`_reverify/rules.md:27`、`03-吃拐一轮秒.md:15`）。

### 4.5 因子计入的判定

- 召唤物/装置造成的伤害与触发计入持有干员；模式限定模组（ISW-α/RA-α/SO-α/SO-β 等）与模式限定天赋计入，条件写明模式、备注注明仅该模式可用（`03-吃拐一轮秒.md:10`、`05-插拔容错.md:20`）。
- 必生效的天赋/特性/模组乘算须计入，含**模组档位固定属性并入面板**（§4.1）与**对敌固定点数增伤**（如「受到的法术伤害提高150点」，对施加该次攻击本身亦生效）；条件成立才生效的档位以「写进条目前提」为计入依据，未写进者取下限并写明理由；概率触发按期望（写明算式）。
- 过载按后半程分段（§2.5 D3）。
- 不可折算倍率的项：元素损伤值本身、固定点数伤害（「每秒 X 点法术伤害」）不计（`03-吃拐一轮秒.md:8`）。

### 4.6 证据与写法纪律

- 一切数值落 `material_datas/PRTS/` 下的 `文件:行号`；行号逐页定位、不得跨页套用；优先复用条目「依据」列已有行号（`_reverify/rules.md:55`）。
- 不写过程语与模糊措辞；拿不准不硬判，给出两套算法（`_reverify/rules.md:49,50`）。
- 「（待验证）」的标注范围见 `docs/concept.md:33`；数值门槛的权威源见 `docs/player-tags-specify.md` 与各 `NN-*.md` 评定标准；术语以 `docs/glossary.md` 为准——三处均只作指针，不在本文重述。

### 4.7 双情形呈现（溢出机制与附加提分）

- **溢出机制**：干员可通过溢出机制把一部分资源（如超上限的棋子/弹药）转化为 TAG 所需输出时，**分别计算两种情形**——「完全溢出」（超额资源按**一瞬间全部结算**计，不计窗口时间）与「完全不溢出」；两种情形的成绩都写进备注（例：望 的 S3 棋子超出上限者自动部署、即时触发）。
- **附加提分**：干员本体即满足 TAG 要求、而召唤物／装置／特勤等附加因素可进一步提高成绩时，备注写明两种成绩——**仅算满足 TAG 要求那部分能力**者、与把**能提高该 TAG 成绩的全部因素**计入者（例：机械师 的召唤物「结构性原理」）。
- **成绩前置**：同一干员在该 TAG 下有多情形成绩时，成绩列在**备注开头**（撰写规则见 `docs/concept.md`「结果展示」）。

### 6.2 与复算作业副本的关系

1. 本文是计算规则的**正本**：只写已定规则与未定项索引，与具体任务无关。
2. `material_datas/tag_pipeline/player_tags/_reverify/rules.md` 是复算任务的**作业副本**：除同源规则外，另含任务范围、逐条字段格式与作业红线；这些附加内容属该任务，不进入本文。

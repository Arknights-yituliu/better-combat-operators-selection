随着明日方舟干员机制的日益复杂，亟待一个更符合玩家需求的干员筛选系统。无论是游玩多年的老玩家，还是新入坑的新玩家，都可以通过这个筛选系统更好地了解各种干员的特性。

## 数据来源
PRTS

## 数据获取计划
将PRTS上的每一个干员页面，包含干员信息主体（以及可能具有的召唤物）的部分爬下来，存到这个项目的material_datas\PRTS里，每个干员具有一个单独的文件夹来存放其内容，因为有的干员具有召唤物，干员和召唤物信息分别提取到两个文件中，存放在同级目录里。

## 注意
在爬取PRTS的时候，需要注意爬取频率，避免触发限流机制。

# 筛选方式
不再通过传统的职业、分支等指标筛选（但是可以通过稀有度筛选），而是通过干员的“机制”进行筛选。这个机制可以是人为定义的。
例如说，筛选TAG有“造成弱点伤害”、“造成元素伤害”、“造成元素损伤”、“帧级结算（帧伤）”、“施加晕眩”、“自身重部署”、“传送敌人”等等，是写在干员的天赋、技能、模组里的信息，而非表面上展现出来的标签。
TAG之间也有层级之分，例如顶层TAG“造成元素损伤”下，有子TAG“造成神经损伤”、“造成灼燃损伤”、“造成凋亡损伤”、“造成侵蚀损伤”。（现行客户端官方另有第五系“狂躁损伤”，但目前没有任何干员施加它，故不设子 TAG。）
除了层级之分之外，还有更进一步的数值筛选，就拿“施加寒冷/冻结”为例，每个干员可以施加多长时间的寒冷？如果进一步施加寒冷，使其转变为冻结，或是直接施加冻结，又可以施加多久？还有的，对于施加晕眩，也有多种施加方式，是“技能期间间歇性的持续施加（例如佩佩）”、“天赋普通攻击概率施加（例如卡达）”、“天赋一次性施加（例如U-Official）”、“技能期间整段晕眩（例如缪尔赛思）”等。诸如此类。这类标准会非常多，因此大多靠人工拟定，但可以按照开发者的需求，让AI来设定开发者可能没有考虑到的部分。目前的考虑是，如果是官方定义的子TAG（例如元素损伤），设定为可筛选的TAG，如果是施加的方式（干员程序实现上的差异）的不同，改为标注在备注里，而对于类似的程序实现方式，可汇总一套一致的备注标注模板。
同级间的TAG可以属于同一类别，例如“施加晕眩”、“施加寒冷/冻结”、“传送敌人”都属于“控制”类别。
同级间的TAG需要按实装时间倒序排序，新机制往往和新干员匹配，有些机制是很老的干员就有，而有些机制是随着新干员的实装同步推出的。
同一个TAG下的干员同样按实装时间倒序排序，不过提供排序选项，让用户在正序和倒序中灵活切换。
用户可选的筛选TAG会非常之多，因此还需要有一个模糊搜索框来筛选“筛选TAG”，用户再从筛选出的筛选TAG里选择TAG来筛选出自己想要的干员。
对于官方设定的TAG，备注里引用游戏内文本作为证据；对于玩家体感类TAG，备注里写该干员在该TAG下能够为玩家的战术提供哪些帮助。
一个干员可能有多个TAG，而每个TAG都需要有自己的条件和备注。

# 结果展示
用户通过多选筛选TAG来筛选出想要找的干员，被筛选出的干员会展示这些信息：
基本信息：干员名称、职业、分支、稀有度、势力、实装时间。
条件：要具备TAG所描述的能力，需要什么样的条件，例如某些干员精二才能解锁具有相应TAG能力的天赋、技能或是模组，若干员在精零1级状态下就具有相应TAG所描述的效果，则填“无”。
备注：任意值得提的内容，范围不限，可以为空，最好写信息加工、筛选后有用的内容，或是特殊隐藏机制，亦或是为了帮助说明写的具体数值，不要写直接就写在干员信息里明晃晃的内容，那样玩家在游戏内直接看不就得了；举个例子，玩家体感TAG“决战歼灭”里的干员维什戴尔，虽然特性里写了是对地，但是三技能期间是具备对空索敌的，这点在游戏内文案无法直接看到，就可以写进备注里。

备注撰写的深层标准（与 docs/player-tags-specify.md 中各 TAG 的判定写法一致）：**条件**字段放硬性达成条件（精英化、模组等级、特殊需求等），**备注**字段放加工后的信息——隐藏机制、特殊用法与具体数值，二者分工明确。凡玩家凭直觉即知、或在游戏内文案一眼可见的内容不写备注。反例：迷狂牢笼不占用部署位是玩家下意识的认知，不必写；值得写的是它的特殊机制“可以阻挡本格内所有可阻挡的敌人”（与属性表阻挡数 0 并存，文案不易直接看出）。对于具体数值，若是PRTS文档里明写了，可以写；对于AI通过计算得出来的数值，也可以写，但只有涉及攻速／攻击间隔换算或倍率相乘、叠乘（含求和、期望、均值）的推算才在备注中加上「（待验证）」字样，供逐条复核；原文数值的加减与单步换算、单步倍数放大、由原文时长与结算间隔直接相除得到的段数、攻击范围格数等都不加。

备注为**自包含文本**：不得以「见某干员条」「同上」「同格另一条」「另见某文件」等方式引用其它条目或文件，重复内容也要各写全。（规范源指针与PRTS证据行号除外。）

备注的**成绩前置**：同一干员在某 TAG 下存在多种情形的成绩时（例如可通过溢出机制把超额资源转化为输出者，或本体即达标、而召唤物／装置／特勤等附加因素可再提高成绩者），应把各情形的成绩列在**备注开头**（先列成绩、再展开细算），便于读者快速定位重点。

对于“荐”的标注，AI可以给出推荐建议，但实际标注必须由开发者人工来。荐的意义在于标注出某个玩家体感TAG下，效果显著高于其他干员的干员。例如对于“次数对策”TAG，我不知晓维什戴尔2技能期间总共会造成多少段伤害，但我知道在她能造成的伤害段数的量级一定是远在赤刃明霄陈3技能之上的，那么AI就可以推荐将“荐”赋予维什戴尔。

# 项目职能
本项目只做干员TAG分类和生产分类结果json的事情，不做UI上的显示，UI上的显示是另一个项目的事情。本项目要做的就是产出结果json，将之复制到另一个项目中映射为UI，供用户们筛选。
本项目仅产出2份json，存放到results目录里：
1. 干员TAG分类结果json，包含官方设定TAG和玩家体感TAG下的所有干员。TAG和干员之间是多对多的关系。每个干员具备的每一个TAG，都需要有一个条件和备注。
2. 战斗术语json，已存放于results\combat_glossary.json。

# 干员特性分析
干员数量太多，需要使用AI模型来帮助分类，但是AI模型并不一定清楚明日方舟的伤害计算、状态施加机制，因此在遇到不能绝对确定的地方时，一定要使用ASK功能向开发者求证。

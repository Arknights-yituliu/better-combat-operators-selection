# 全表扫描流程（不漏扫）

> 用途：任何「按 TAG 逐行扫描／重判」的作业——新增或修订评定标准、口径变更、全库重扫、成员复核——**一律按本流程执行**。目的是根除「只改了一部分、其余静默跳过，发现了再改、没发现就永远不改」这类缺陷。
> 与其它文件的关系：撰写规则见 `docs/concept.md`；判定依据见 `docs/rulings.md`（先查台账）；本条只管**流程**。

## 1. 名单文件（每批一份）

- 位置：`_out/名单-<批次名>.md`（`_out/` 为临时批次目录，已 gitignore；随交付附上供开发者抽验）。
- 一份名单文件对应**一批**扫描（通常＝一个分文件，或一个分文件的一段）。
- 表头固定四列：

| 干员 | 决断 | 理由 | 依据 |
|---|---|---|---|
| 缪尔赛思 | 改（条件、备注） | 3技能「浅层非熵适应」持续 15 秒内对阻挡目标持续晕眩 → 计入「长效控制」子 TAG；越界幅度按流形落点重写 | `缪尔赛思/缪尔赛思.md:130` |
| 崖心 | 不改 | 最高只达「较大力」，门槛为「大力」 | `崖心/崖心.md:84,103,128` |
| 遥 | 待裁 | 技能2 的「浮光泡影目标数+1」是否计庇护对象数，评定标准未写 | `遥/遥.md:109-112` |

- **决断**取值闭集：`改`（写明改了哪几列）／`不改`（写明为何不改）／`待裁`（写明争议点，路由根目录《待裁定.md》）。
- **理由**必须具体——「无关」「无需」「已处理」这类空话不算理由。
- **依据**一律 `文件:行号`（相对 `material_datas/PRTS/`）——**判「不改」的也要给依据**，用来证明该行被真正读过。

## 2. 逐人决断纪律

1. 扫描范围＝该批**全部行**（含各子表行、含同一干员的多行），不得按印象抽样、不得跳行。
2. 每一行必须显式落到名单文件里——**名单里没有的行视为未扫描**，不得进入回填。
3. 判定以该 TAG 的**评定标准**与 `docs/rulings.md` 台账为准；查得到按裁定办，查不到的写 `待裁`，**不要自创规则**。
4. 名单文件与回填用的 `_out/<批名>.json` 一一对应：名单里判「改」的每一行，都必须在 JSON 里有对应条目；反之亦然。

## 3. 复核（强制，不可省）

名单与 JSON 写完后，**另起一个复核代理**（不复用写手的上下文），逐条证伪：

- 对每个「不改」：回语料抽验，专门找「其实该改」的反例；
- 对每个「改」：核对回填文本与所列 `文件:行号` 是否相符、有无漏写硬性前提；
- 输出**复核结论**：`通过`，或逐条列出问题（含反例与出处）。

**复核未通过 → 修正后重跑复核；通过后才允许 `_apply_batch.py` 回填。**

## 4. 批次划分建议

- 单文件行数 ≤ 40：可一批跑完；更大者按子表或行区间切批（每批都在名单文件里写清范围）。
- 跨文件的口径变更（如「模组代号写法」「成绩块标签」）：按文件切批，每批同样出名单文件＋复核。

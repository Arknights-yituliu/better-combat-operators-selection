# 作业记忆包（agent-primer）

> 用途：**新会话与新派发的子代理开工前必读**。这里放「不知道就会推断错、并且真的推断错过」的东西——游戏侧的解锁关系、仓库侧的作业纪律、以及一份反面清单。
> 本文只放**常识与红线**；规则正文在各自的权威源（`docs/concept.md`、`docs/calc-rules.md`、`docs/output-standard.md`、各 `NN-*.json`），裁定既往在 `docs/rulings.md`。三者冲突时以规则正文与裁定台账为准。
> 维护：爬虫剥离规则、交付格式、命令有任何变动，**本文必须同步**（它一旦过期，子代理就会照着过期记忆办事）。

## 一、游戏常识（不写下来就会被凭空推断的那些）

### 解锁关系
| 事实 | 说明 |
|---|---|
| **技能按精英阶段开放** | 技能1＝精英0、技能2＝精英1、技能3＝精英2。语料逐干员带 `**技能N（精英X开放）**` 标记（全库 429／410／144 例，另有少量例外形态）——**以语料标示为准，不得凭记忆推断**。 |
| **专精（Rank Ⅰ–Ⅲ）的前置＝精英2 ＋ 该技能等级 7** | **语料里查不到**（`技能升级材料` 一节在爬取时被剥离）。要写「专精3」就必须写精英2——只写「精英1；2技能（专精3）」是自相矛盾的。 |
| **模组解锁的前置＝精英2** | 同上，`模组解锁任务`／`解锁需求与材料消耗` 两节也被剥离，语料里只有模组本身的数据。条件里点名任一档模组，就等于隐含精英2。 |
| **2★及以下（1★／2★）不具备专精** | 这两档稀有度的技能没有专精等级——语料里没有专精行，条件里不写专精、备注也不取「专精3」数值。 |
| 召唤物／装置随所属干员 | 无独立解锁条件。 |

**推论（写条件时直接照用）**：写 `3技能` 即隐含精英2；要专精就得精英2；点名模组就得精英2。**只写「精英1」时，必须确认该能力在精英1 状态下真的完整**（技能2 是否为精英1 开放、有没有专精或模组前提）。

### 数值体系
- **面板攻击力**＝满信赖 ＋ 最高精英化阶段满级 ＋ 有效潜能最高档 ＋ 条件点名模组档位的固定属性（攻击+N）。**取数只走 `tools/prts_stats.py`**（`--panel` 给面板与组成式），不要手抄语料。
- 面板、潜能、模组各档固定属性的机读来源：`agent_workspace/tag_pipeline/stats.json`。
- 模组档位标记 `**模组等级N**` 是本仓库爬虫写的（不是 PRTS 原文），级别可靠；模组固定属性行是**多字段连写**（`攻击 +65攻击速度 +7`），按内容切分。
- **默认敌人＝纯木桩**：一切演算默认敌人为 0 防御力、0 法术抗性、0 闪避／免伤、无其它任何减伤。据此，作用于敌方防御／法术抗性**数值**的效果（减防、降抗、无视防御／法抗、穿透）**无增量、不计入**；作用于**承伤倍率**的增伤（脆弱、通缉、「受到的伤害提高 X%」）照常计入（`docs/rulings.md`「默认敌人：纯木桩」）。木桩口径只作用于敌人**属性**，不取消状态类前提（被阻挡、停顿、战栗等照旧写进条件）。
- **模组取档**：按**绝对贡献**取「对本 TAG 有帮助的最高档」——不得因更高档拉低比值／稀释均值而改取低档；**多条通用模组之间平权**、取成绩更高者；持**特限证章**（模式限定模组）者，通用线与特限线**分别计算**、UI 分别展示且特限线优先（`docs/ui-render-rules.md`），无特限证章者默认各模组增伤条件均满足、取更高者并把条件写进条件；潜能的取档判据同模组（`docs/rulings.md`「模组取档」「特限模组与通用模组：分别计算、特限优先展示」「潜能取档」）。**计算规则只作用于玩家体感 TAG**。

### 术语
游戏机制名词（过载、元素损伤、屏障/护盾/闪避、吟唱、魔力…）一律以 `docs/glossary.md` 为准；机制判别原则与易错对照见 `docs/mechanism-understanding.md`（**判别原则以它为准**，其中的计数与举例如有出入以现行文件为准）；已知的判断陷阱见 `docs/verification-complaints.md`；**各模组的「※」隐藏机制条文**（模组效果格里 PRTS 标 `※` 的补充说明，如距离增伤的门槛格数）查 `docs/module-hidden-mechanics.md`（由 `tools/module_notes.py --emit` 从 `docs/temp.txt` 生成，含按干员／按类别两套索引）。**元素损伤按元素值（EP）机制**：初始满值（普通/精英 1000、领袖 2000）、爆发冷却内不可累积、结束重置后重积——涉爆条节奏的演算先读 `docs/mechanism-understanding.md`「元素值（EP）与爆条节奏」。

## 一之二、扫描类作业必读（不漏扫）

任何「按 TAG 逐行扫描／重判」的作业（新增或修订评定标准、口径变更、全库重扫、成员复核）**一律先读 `docs/scan-protocol.md`**：每批出一份名单文件（`agent_workspace/_out/名单-<批次>.md`，逐人写「改／不改／待裁＋理由＋`文件:行号`」），**全表逐人决断完毕**后才允许回填，随后**另起复核代理**逐条证伪、通过才放行。名单里没有的行＝未扫描，不得进入回填。

## 二、仓库作业常识

- **证据制**：一切判定以 `material_datas/PRTS/` 下的 `文件:行号` 为据；**证据只写进成员表的「依据」列**，不得出现在条件/备注正文里（结果 JSON 更不得携带）。
- **数值不手抄**：面板与档位取 `tools/prts_stats.py`；产物里的每个 `面板NNN` 由 `tools/verify_numbers.py` 回头校准。
- **自创代称必须登记**：任何代称、缩写、自编号（含新引入的符号、块类名、脚本别名）一律登记进 `docs/term-map.md`，未登记不得在交付文本里使用。
- **撰写格式**：条件与备注的写法（条件分条、备注分块、能力块自足、面板组成式、内部代号禁入产物）见 `docs/concept.md`；产出结构与省略规则见 `docs/output-standard.md`。
- **裁定既往不咎但要查**：任何「是不是该取更高档」「这类效果算不算计入」的问题，**先查 `docs/rulings.md`**；查不到再走《待裁定.md》流程，且裁定后必须折入正本并在台账登记。
- **工具链**（`crawlers/`、`tools/`、`.claude/skills/` 与根目录入口，全部 `python -X utf8` 运行）：
  | 脚本 | 作用 | 看什么 |
  |---|---|---|
  | `tools/prts_stats.py` | PRTS 语料 → `stats.json`；`--panel` 复算面板 | `--check` 覆盖率与异常应为 0 |
  | `tools/verify_numbers.py` | 产物数值校准（面板／档位／恒等式／内部代号／因子覆盖） | 「数值可疑」应为 0；「档位取舍已复核」是**人已裁定过的不取档**，不是待办 |
  | `tools/generate_results.py` | 生成结果 JSON；`--check` 跑规范校验与**文本 lint** | 文本 lint 应为 0 |
  | `.claude/skills/tag-batch-rewrite/scripts/audit_text_migration.py` | 对比 HEAD 查重排守恒（数字/依据/结构） | 三类均应为 0；`ACCEPTED` 是**已复核放行的有意改动** |
  | `crawlers/strip_prts_noncombat.py --audit` | 证据层：`文件:行号` 是否仍指向剥离前的原文 | 失效／未解析应为 0 |
  | `recommend_gui.py --check` | GUI 侧按 `docs/output-standard.md` 校验结果 JSON | 0 错误 0 提醒 |
  | `tools/module_notes.py` | 解析 `docs/temp.txt`（PRTS《模组》页快照）→ `docs/module-hidden-mechanics.md` | `--list` 只看统计；`--emit` 写出 |

## 三、反面清单（这些错真的发生过）

0. **未经裁定自作主张** —— 开发者明确要求改的才动；**你自己发现「可能需要修改」的，必须先问过开发者再决定**（写进《待裁定.md》，不要动手）。代表人物自述：「你发现可能需要修改的，必须问过开发者再决定」。同理，**不要自行放宽自己的工具权限**（那属于未经请求的扩大）。
0b. **自创词不解释** —— 交付文本里出现任何自造词／简称（「准联动」「自身变硬」之流），必须当场写明它该怎么理解；见名知意是运气不是规范，新词同时登记 `docs/term-map.md`。
1. **凭记忆推断解锁条件** —— 把「精英1＋2技能（专精3）」写成达标条件（专精需精英2）；把只在精英2 才解锁的东西写成精英1。→ 读语料的 `**技能N（精英X开放）**` 行。
2. **只读评定标准、不读「约定」** —— 各 TAG 的取档、计数、双情形规则都在同一文件的「约定」节里，跳过它就会自创口径。
3. **把工具的通用通报警当成必须执行的结论** —— `tools/verify_numbers.py` 的「档位未取满」只说明「存在更高档且有增益」，**该档对本 TAG 有没有帮助要按本 TAG 判据裁定**；裁定为「不取」的登记在 `REVIEWED_TIERS`（**脚本侧放行表，不进产物**——`说明` 只留口径与特殊计数方式，不写「为何不取更高档」；仅在条件点名了非满档时保留一句档位理由）。
4. **把子代理的自述当证据** —— 子代理的 `why`/报告是线索不是依据；合入前必须回到语料核对。
5. **把「没用模组」当默认** —— 漏并模组档位固定属性会让面板偏小，进而整条成绩偏小（逻各斯 788 vs 855）。
6. **在行内重述评定标准** —— 门槛（≥2000%、≥6 格、≥25 次…）只在评定标准里写一遍，条目里不重复。
7. **在产物里留内部代号** —— 范围代号（`代号 3-18`）、`S1/S2/S3`、`表 2A`、`路径⑤`、`R7`、分文件名，全部要改写为人话。**模组代号是例外、必须写进产物**：统一写「中文线名（代号）」（`X模组3级（HOK-X）`、`集成战略特限模组3级（ISW-α）`）；写成人话却丢了代号同属缺陷。
8. **凭「表会变长」或「与别的 TAG 重叠」而设排除** —— 干员可属多个 TAG，重叠不是排除理由；排除必须来自能力判据（次数对策的排除⑦就是反面教材，已撤）。
9. **拿旧文本当依据** —— 旧文本里的数字可能是自造转写（斩业星熊旧行的「约 8 秒」）。一切回语料。
10. **改完不跑审计** —— 改分文件后必须跑：`tools/generate_results.py --check` → `tools/verify_numbers.py` → `.claude/skills/tag-batch-rewrite/scripts/audit_text_migration.py`（改到行号引用时加 `crawlers/strip_prts_noncombat.py --audit`）。
11. **把作用于敌方防/抗数值的减益计入** —— 默认敌人是 0 防 0 抗的纯木桩，减防／降抗／无视防御与法抗／穿透在它身上不产生任何增量，只有承伤倍率型增伤（脆弱、通缉）才计入；同理，**为把比值／余量做好看而改取更低的模组档**也是反面——取档按绝对贡献判（见「数值体系」）。

13. **跨块窗口抽取外部数据 → 幻觉归属** —— 从站点/脚本等**结构化源**里抽「某干员×某属性」时，用「技能名后 N 字符窗口」这类**邻近搜索**会把相邻对象的数据泄漏过来（真实案例：首轮把**麒麟R夜刀3「空中回旋乱舞」的「巨型敌人」分支**泄漏给**仇白**，而仇白三个技能均无分支）。正确做法：**括号配对逐对象解析**（逐个 `skillN:{...}` 对象内部取字段），并且**落盘前至少回源抽检 2–3 条**；站点本地副本 `agent_workspace/_out/_arkdps_main.js` **只含 100 名干员**，副本外的行**不得臆造分支**。同理，「上一轮产出的印象」不是数据源——**禁止成功记忆**，一切回源重读。

12. **在条目里写与本 TAG 无关的信息** —— 为一个 TAG 描述某干员时，只写与这个 TAG 评定对象直接相关的成绩、能力与算式；该干员的其它能力（特性、别的天赋、别的技能、无关模组线）整块不写，与本次纳入无关的演算和「未计入：X」条目也不写。判据是「这与本 TAG 判的这件事有关吗」，不是「顺便交代一下」；**被实际纳入计算的面板组成式与算式照留**。注意别做过头：**符合本 TAG 判据的能力一项都不能漏**（`docs/concept.md`「备注分块」）。

## 四、派发子代理时的必读清单

派「TAG 改写／复算／数据修复」类子代理时，**用 `.claude/agents/tag-rewrite` 代理类型**，并在 prompt 里至少给出：

1. **必读三件**：本文（`docs/agent-primer.md`）、`docs/rulings.md`、目标分文件（`agent_workspace/tag_pipeline/player_tags/NN-*.json` 或 `official_tags/[A-I]-*.json`）。
2. **本 TAG 的判据出处**：要求它先读该文件的「评定标准」与「约定」，并声明「以本文件为准」。
3. **产出格式**：写 JSON 到 `agent_workspace/_out/<批名>.json`（键＝干员名，值＝`{condition, remark, why}`），**不直接改分文件**——由主进程统一回填（按「干员」列名结构化定位、只设 条件/备注 两个字段，其余字段原样保留）。
4. **自查命令**：`tools/verify_numbers.py --only <TAG>` 与 `tools/prts_stats.py --check`，并要求回报关键输出。
5. **不许自作主张的清单**：不得改依据列、不得增删成员行、不得改评定标准（发现规则冲突时报告，不自行其是）；工具报警按本 TAG 判据裁定，裁定结论进 `REVIEWED_TIERS` 或台账。

> **本条只适用于 TAG 改写／复算／数据修复类任务。版本更新类任务（新干员／新模组）不适用——它的开工件与阅读预算在 `docs/version-update-quickstart.md` §1，主进程按那份清单派单，不要让子代理再读本文与 `rulings` 全文。**

# 玩家体感 TAG 干员名单判定 · 共享作业说明（读我）

> 目的：为 `docs/player-tags-specify.md` 中开发者拟定的 12 个**玩家体感 TAG**，逐一产出"该 TAG 下的完整干员名单 + 条件 + 备注"。
> 每个执行者（agent）负责一个 TAG，把结果写到本目录的一个 md 文件里，主协调者再合并为 `docs/player-tags-members.md`。

## 0. 项目背景（必读）

- 本项目为明日方舟干员筛选系统生产数据。已有两类 TAG：
  - **官方定义类 TAG**：`docs/official-tags-members.md`（TAG 数与关系数以该文档 §3 为准），机读字典在 `material_datas/tag_pipeline/`（`catalog.json`＝脚本唯一读取的字典；`merged.json`／`final_lists.tsv` 由 `official_tags/_merge_official_to_docs.py --sync-dicts` 同步；`deterministic.json` 为基础属性快照；维护层 `official_tags/`）。
  - **玩家体感类 TAG**：`docs/player-tags-specify.md`（开发者拟定的正式玩家 TAG，即本次任务的定义来源），名单结果见 `docs/player-tags-members.md`；线索来源＝PRTS 原文复核。
- 本批共 12 个 TAG：决战歼灭、次数对策、吃拐一轮秒、远程消耗、插拔容错、初动增加、充电、拐杖、保人、大力推拉、阻挡数5、阵容组合。

## 1. 数据源（判定以 PRTS 原文为准）

| 源 | 用途 |
|---|---|
| `material_datas/PRTS/<干员>/<干员>.md` | **主证据源**。含 特性/天赋/技能/模组/属性/获得方式(上线时间)/召唤物信息。技能表按等级列出（Rank Ⅲ=专精3，7=7级）。 |
| `material_datas/PRTS/<干员>/*.md` | 同目录的召唤物文件（如 温蒂/工程蓄水炮.md）。**召唤物效果计入持有干员。** |
| `material_datas/tag_pipeline/deterministic.json` | 解析好的基础属性（再部署/阻挡/费用）与召唤物数据（block/slots/etype）。 |
| `material_datas/tag_pipeline/final_lists.tsv` / `merged.json` | 官方 TAG → 成员名单（按实装倒序），用于交叉锚定。 |
| `docs/official-tags-members.md` | 官方 TAG 定义与完整名单（含备注评定标准）。 |
| `docs/mechanism-understanding.md`、`docs/verification-complaints.md` | 机制判别评定标准与历史踩坑记录（避免重蹈覆辙）。 |

## 2. 判定铁律（项目既有约定，务必遵守）

1. **一切判定以 PRTS 原文（文件:行号）为证据**，不凭模型记忆；拿不准的标 `[待考]` 并写入"待开发者确认"。
2. **施加方向是第一属性**：区分"对友方/自身/敌人/召唤物"。本批 TAG 全部是**对友方/对团队**的体感能力（除个别如推拉是对敌），不要把"自身获得"误判成"能为友方提供"。
3. **召唤物/装置效果计入干员**（如酒神3技能生成的迷狂牢笼计入酒神）；**模式限定模组（ISW-α / RA-α 等集成战略/生息演算限定）同样计入**——但必须把模式限定写进「条件」（如"需开启 ISW-α 模组"），并在备注中注明该效果仅在该模式可用。
4. **区分同名不同物**：屏障(吸收值)/护盾(按层挡一次)/闪避/抵挡、脆弱(受伤↑)/攻击力加成、灼烧DoT/灼燃损伤、晕眩/停顿/束缚/战栗/麻痹……分类参照 `docs/official-tags-members.md` §2 与 `mechanism-understanding.md`。
5. **不凭当期强度**：只收机制层面成立、跨版本稳定的能力；"新神/退环境/超大杯"类强度结论不收。
6. 干员用**正式名**（与 PRTS 文件夹名一致，如"史尔特尔"不写"42"、"假日威龙陈"不写"水陈"）；异格/同名分别列（如 阿米娅(医疗)）。

## 3. 条件 / 备注 的写法（来自 `docs/concept.md` 与 specify 文档）

- **条件**：硬性达成条件。例：`精英2`、`精英2；3技能专精3`、`精英2；Y模组1级`、`精英1`；以及目标限制（`仅对重装生效`、`仅限高台`、`仅限攻回/受回干员`、`需在场上`）。若干员精零1级即具备该能力 → 写 `无`。
- **备注**：信息加工后的内容——**具体数值、持续时间、隐藏机制、特殊用法、战术帮助**。不写游戏内一目了然的话；没东西可写就写 `—`。数值取 PRTS 原文，标注关键等级评定标准（专三/7级/Rank Ⅲ）；只写对筛选/使用有用的，不必抄全文。
- **一名干员的多项能力只要各自符合本 TAG 的评定标准都要写**：条件写全各能力的硬性前提，备注逐项写清；不因与其它能力重叠、幅度较小或已有更强项而省略。
- **模组档位**：判定能力受模组增强者，「条件」写明模组名与等级、「备注」取该档位数值；同干员多模组时取对**本 TAG** 有增强的模组（不同 TAG 各行可分别取不同模组）；不用「更佳/可选」类模糊写法，模组无关于本 TAG 者不写。
- 「条件/备注」的完整标准与反例、正例见 `docs/concept.md`「结果展示」一节（本文件不再复述）。

## 4. 产出格式（每个 TAG 一个文件）

文件名由主协调者在派发时指定（如 `01-决战歼灭.md`），统一写为：

```markdown
# <TAG名>

## 评定标准
（3–8 行：纳入标准、排除标准、边界处理。引用 specify 原文的关键句。）

## 成员表（按实装时间倒序）
| 干员 | 条件 | 备注 | 依据 |
|---|---|---|---|
| 维什戴尔 | 精英2；3技能 | ……（含数值/隐藏机制） | 维什戴尔/维什戴尔.md:133 |

## 边界与排除记录
- 纳入存疑（未进主表）：<干员> —— 原因（如数值不达线/仅自身/证据不足）
- 明确排除：<干员> —— 原因（如 脆弱≠攻击力加成）

## 待开发者确认
- <问题>（附证据与两种处理）

## 检索记录
- 关键词/正则：……（命中 N 文件 → 人工复核 M 人）
```

### 排序与时间
- 成员表按**实装时间倒序**（新→旧）。上线时间从 PRTS `## 获得方式` 表格 `上线时间 | YYYY年M月D日` 提取；同日的按干员名拼音/原表顺序稳定排序即可。
- 依据列写 `文件:行号`（相对 `material_datas/PRTS/`，多行用逗号分隔），必须真实存在。

## 5. 检索与效率建议

- 用 Grep（ripgrep，支持中文）全库检索关键词/正则，再用 Read 带 offset 精读命中段；技能区在 `## 技能` 与 `## 后勤技能` 之间，天赋区 `## 天赋`–`## 潜能提升`，模组 `## 模组` 起。
- 技能表很长（每技能 13 行），优先读 **Rank Ⅲ（专精3）**与 **7 级**行，以及"备注(※)"行（隐藏机制多在此）。属性表在 `## 属性`。
- 交叉锚定：先用 `final_lists.tsv` / `merged.json` 缩小候选（如"为他人回复技力"=E_charge），再逐一回 PRTS 核对；官方 TAG 名单不全时以 PRTS 全库检索补全。

## 6. 质量要求

- **宁缺毋滥、宁标待考不硬判**：每条成员都要能落到 PRTS 原文；证据不足的进"边界与排除记录"或"待开发者确认"。
- 同名干员/召唤物、异格（如 凛御银灰 vs 银灰、怒潮凛冬 vs 凛冬、凯尔希·思衡托 vs 凯尔希）不得混淆。
- 完成后在回复中给出：文件路径、成员数、最重要的 3 条不确定点。
